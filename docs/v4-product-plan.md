## ۱. تصمیم نهایی و مرجع نسخه
این سند جایگزین طرح ۳.۰ و الحاقیه‌های معماری آن است؛ راهنمای همراه نسخه ۴.۰ نیز جایگزین دستورهای قبلی ساخت می‌شود. اسناد قدیمی فقط سابقه‌اند و نباید هم‌زمان به سازنده به‌عنوان دستور معتبر داده شوند. این بازنویسی، طرح و معیار آزمون است؛ نرم‌افزار یا مدل روی دستگاه حامد در این نوبت اجرا نشده است.

خواسته قطعی جدید: یک وب‌اپ/PWA که کاربر در خود آن مدل هوش مصنوعی را انتخاب، دانلود، ذخیره و اجرا کند؛ بدون Ollama، LM Studio، Termux، Python، localhost inference server، افزونه یا برنامه واسط. گوشی و ویندوز هر کدام مدل و داده خود را دارند؛ گوشی پل لپ‌تاپ نیست.

در دو Markdown قبلی جست‌وجوی لفظ Ollama نتیجه نداشت؛ بااین‌حال طرح ۳.۰ از llama.cpp بومی و Kotlin LiteRT-LM شروع می‌کرد و در بخش وب، مدل آفلاین پیشرفته را به اندروید بومی موکول کرده بود. این تفکیک نادرست/ناقص برای نیاز فعلی اصلاح می‌شود: اجرای آفلاین مدل داخل مرورگر از اولین بسته تحویل الزامی است. اجرای پس‌زمینه قابل اتکا موضوع جداگانه است.

**قطعی‌ها:** پروژه جدید، فارسی RTL، Windows Snapdragon X Plus با 16GB RAM و Pixel 9 Pro Fold، اولین اتصال فارکس و طلا از cTrader Demo، هر دو دستگاه تحلیل مستقل، فقط دستگاه منتخب مجاز به درخواست سفارش، تأیید دستی، سقف مجموع هزینه جاری ۲۰ دلار استرالیا در ماه. با درخواست جدید، پیپرتریدینگ و بک‌تست پیشرفته و مسیر ترید آنلاین نیز جزو طرح اصلی‌اند. آنلاین به معنی قیمت زنده/Paper Live یا اجرای بروکر Demo/Live تفکیک می‌شود؛ پیاده‌سازی مسیر Live در scope است، فعال‌سازی پول واقعی نیازمند انتخاب صریح حساب و تأیید مالک است. پشتیبانی تبلت به دستگاه/مرورگر واقعی مشروط است؛ مدل تبلت هنوز اعلام نشده.

پیشنهادهای مهندسی این سند: WebLLM به‌عنوان مسیر اصلی، مدل‌های رتبه‌بندی‌شده زیر برای آزمون، gateway امن بروکر، سیاست‌های عددی و پنج بسته تحویل. این پیشنهادها ادعای انتخاب تأییدشده مدل یا برتری آزمایش‌شده نیستند. فعال‌سازی Demo وابسته به پذیرش سیاست ریسک و معماری gateway توسط مالک است.

## ۲. آفلاین دقیقاً یعنی چه؟
بعد از دانلود کامل، وب‌اپ باید بدون اینترنت دوباره باز شود و با مدل ذخیره‌شده به سؤال تازه درباره snapshot یا فایل محلی پاسخ واقعی تولید کند. فقط باقی‌ماندن آخرین پاسخ روی صفحه، آزمون آفلاین نیست.

| قابلیت | بدون اینترنت | شرط |
| :--- | :---: | :--- |
| رابط، تنظیمات و journal محلی | بله | app shell و داده قبلاً ذخیره شده باشند |
| تحلیل مدل و گفت‌وگو درباره داده محلی | بله | runtime، tokenizer و همه وزن‌ها آماده باشند |
| replay و محاسبات ریسک تاریخی | بله | داده و تنظیمات مربوط موجود باشند |
| قیمت و خبر تازه | خیر | اتصال به منبع لازم است |
| سفارش، لغو یا اصلاح سفارش Demo | خیر | اتصال و احراز هویت و وضعیت تازه لازم است |
| اجرای بی‌وقفه پس از قفل/بستن مرورگر | تضمین نمی‌شود | PWA و Worker سرویس دائمی نیستند |

WebGPU مسیر GPU است، نه وعده استفاده از NPU. وجود NPU در Pixel یا Snapdragon به‌تنهایی به معنی دسترسی مرورگر به آن نیست. تشخیص قابلیت و بارگذاری واقعی لازم است. WebNN مسیر جداگانه‌ای است و backend/مدل/مرورگر مشخص باید تأیید شود. نصب PWA محدودیت RAM یا تعلیق مرورگر را حذف نمی‌کند.

## ۳. نتیجه بررسی موتورهای اجرای وب

### مسیر اصلی: WebLLM
WebLLM برای inference داخل مرورگر با WebGPU طراحی شده؛ API گفت‌وگو، streaming، Worker و خروجی ساختاریافته دارد. مدل باید artifact سازگار MLC و کتابخانه WASM منطبق داشته باشد. فایل GGUF یا safetensors دلخواه را نمی‌توان صرفاً با تغییر نام مدل به آن داد. نسخه بسته، model library و revision وزن‌ها باید با هم قفل شوند. فهرست main مخزن، تضمین حضور مدل در نسخه npm نصب‌شده نیست.

### مسیر مقایسه‌ای: LiteRT-LM Web
مستند رسمی JavaScript در تاریخ بررسی، Early Preview و text-in/text-out با WebGPU است. فایل‌های مشخص web برای Gemma 4 E2B و E4B را معرفی می‌کند؛ پشتیبانی نسخه بومی، NPU یا تصویر/صوت مدل پایه به وب تعمیم داده نشود. ابتدا فقط در آزمایشگاه مدل و پشت feature flag قرار می‌گیرد.

### مسیر مکمل: Transformers.js و ONNX Runtime Web
برای مدل‌های embeddings، ONNX، طبقه‌بندی، گفتار و برخی مدل‌های مولد مناسب است. CPU/WASM و GPU/WebGPU بسته به graph و operators قابل استفاده‌اند. وجود ONNX به‌تنهایی اثبات اجرای مدل روی Pixel WebGPU نیست. این مسیر برای fallback سبک یا قابلیت تخصصی افزوده می‌شود؛ از روز اول سه موتور سنگین وارد bundle نشوند.

### گزینه‌های غیرپیش‌فرض:
* **wllama:** اجرای llama.cpp در WebAssembly داخل مرورگر است و با Ollama سروری فرق دارد؛ اما مسیر CPU/GGUF، محدودیت حافظه و شرایط multithreading دارد. برای fallback پژوهشی قابل بررسی، نه موتور پیش‌فرض مدل سنگین گوشی.
* **Chrome Prompt API / Gemini Nano:** جایگزین عمومی این محصول نیست: مستند فعلی Android/iOS را پشتیبانی‌شده نمی‌داند و فارسی در زبان‌های اعلام‌شده Prompt API نیست. مدل نیز توسط مرورگر مدیریت می‌شود، نه کاتالوگ آزاد برنامه.

## ۴. کاتالوگ مدل‌ها و اولویت واقعی
بهترین مدل برای این برنامه، مدِل برنده آزمون فارسی، درستی شواهد، زمان پاسخ و پایداری روی دستگاه خود حامد است؛ نه لزوماً مدل بزرگ‌تر یا رتبه اول benchmark عمومی. هیچ مدل این فهرست به‌عنوان معامله‌گر سودآور تأیید نشده است.

| مدل | مسیر موجود | نقش پیشنهادی |
| :--- | :--- | :--- |
| **Qwen3.5-0.8B** | WebLLM/MLC؛ نیز ONNX منتشر شده | اثبات اولیه و حالت سبک؛ نه تحلیل‌گر نهایی صرفاً به علت سرعت |
| **Qwen3.5-2B** | WebLLM/MLC؛ نیز ONNX موجود | نامزد متعادل موبایل؛ فقط پس از آزمون واقعی |
| **Qwen3.5-4B** | WebLLM/MLC؛ نیز ONNX موجود | نامزد کیفیت بالاتر ویندوز؛ اختیاری روی Pixel پس از آزمون |
| **Qwen3-1.7B و Qwen3-4B** | رکوردهای WebLLM/MLC | مسیر برگشت اگر ترکیب جدید Qwen3.5 شکست خورد |
| **Gemma 4 E2B** | فایل web + LiteRT-LM Web | رقیب جدی برای مقایسه؛ runtime پیش‌نمایش |
| **Gemma 4 E4B** | فایل web + LiteRT-LM Web | نامزد کیفیت بالاتر؛ سنجش حافظه و کندی ضروری |
| **Qwen3.5-9B / Qwen3-8B** | رکورد WebLLM/MLC | فقط آزمایش پیشرفته ویندوز، نه دانلود پیش‌فرض |
| **Phi-4-mini-instruct** | مدل 3.8B و مسیرهای runtime/ONNX قابل بررسی | مقایسه منطق؛ بسته وب دقیق باید جدا تأیید شود |
| **SmolLM3-3B** | مدل و ONNX از HuggingFaceTB | مقایسه انگلیسی؛ فارسی جزو شش زبان اصلی اعلام‌شده نیست |
| **Gemma 3 1B / Llama 3.2 1B-3B** | مسیرهای وب موجود | شاهد مقایسه و fallback؛ نه انتخاب خودکار فارسی |

### حافظه: عدد فایل با RAM برابر نیست
در config فعلی WebLLM برای Qwen3.5 با q4f16 و context 4096، برآورد VRAM حدود ۱۶۲۹، ۲۲۴۵، ۳۸۶۸ و ۶۴۳۳ مگابایت برای 0.8B، 2B، 4B و 9B ثبت شده است. این اعداد اندازه دانلود یا مصرف کل تب نیستند و روی Pixel اندازه‌گیری نشده‌اند. 2B، 4B و 9B در همین config با `low_resource_required=false` آمده‌اند؛ بنابراین وعده قطعی اجرای گوشی نمی‌دهیم.

فایل web مدل Gemma 4 E2B حدود ۲.۰۱ گیگابایت و E4B حدود ۲.۹۷ گیگابایت است؛ این‌ها فایل web هستند، نه اندازه نسخه native. مخزن MLC برای Qwen3.5-4B حدود ۲.۳۹ گیگابایت نشان می‌دهد؛ حجم دانلود دقیق باید جمع فایل‌های موردنیاز manifest و runtime باشد. وزن مدل تنها بخشی از حافظه است؛ GPU buffers، کپی‌های موقت، chart، مرورگر و سیستم‌عامل نیز مصرف دارند.

### ترتیب انتخاب
ابتدا smoke test با 0.8B یا fallback Qwen3-1.7B؛ سپس 2B و 4B در همان harness؛ سپس Gemma E2B و در صورت ظرفیت E4B. برای هر دستگاه یک مدل مستقل انتخاب می‌شود. اگر هیچ مدل معیار کیفیت را پاس نکرد، برچسب AI_READY داده نشود؛ replay و ابزارهای محاسباتی بمانند و تصمیم مدل برای Demo بسته بماند. بزرگ‌بودن دانلود نشانه کیفیت قابل استفاده نیست.

مدل‌ها روی disk می‌توانند چندتا باشند، ولی در هر لحظه فقط یک مدل مولد در حافظه باشد. نقش Analyst و Critic به‌ترتیب روی همان مدل قابل اجراست؛ این دو «عامل مستقل با دانش مستقل» نیستند. مدل دوم فقط پس از unload اول و با ثبت هزینه تعویض فعال شود.

## ۵. مرکز مدل داخل برنامه
صفحه «مدل‌های آفلاین» بخشی اصلی از محصول است، نه تنظیمات پنهان توسعه‌دهنده:
* **هر کارت:** سازنده، مدل پایه، context، backend، quantization، revision، artifact، مجوز، حجم واقعی دانلود، فضای لازم تخمینی و وضعیت آزمون همان دستگاه.
* **دکمه‌ها:** دانلود با رضایت، لغو دانلود، ادامه از فایل‌های سالم کامل‌شده، بارگذاری، توقف تولید، آزادکردن حافظه، حذف مدل و اجرای تست آفلاین.
* **برچسب جداگانه:** برای «دانلودشده»، «در حافظه»، «آفلاین‌تأییدشده» و «آزموده‌شده برای تحلیل».
* **Progress بایتی دانلود:** از progress ساخت shader/بارگذاری جدا باشد؛ درصد ساختگی یا timer به‌جای دانلود واقعی ممنوع.
* **رضایت صریح:** مدل جدید خودکار دانلود نشود؛ قبل از مصرف چند گیگابایت اینترنت و فضای ذخیره رضایت گرفته شود.
* **بررسی storage estimate:** پیش از دانلود storage estimate، پس از درخواست کاربر persist و نمایش نتیجه.
* **تفکیک داده‌ها:** پاک‌کردن model cache نباید journal، تنظیمات یا outbox را پاک کند. ارتقای app نیز نباید همه‌ مدل‌ها را بی‌دلیل دوباره دانلود کند.
* **استقلال دستگاه‌ها:** تمام مدل‌ها و وابستگی‌های لازم روی هر دستگاه جدا دانلود شوند؛ انتقال خودکار فایل‌های بزرگ از دستگاه دیگر فرض نشود.
* **حالت‌های مدل:** NOT_INSTALLED، DOWNLOADING، VERIFYING، DOWNLOADED، LOADING، READY، GENERATING، UNLOADING، ERROR و EVICTED. وضعیت OFFLINE_VERIFIED نتیجه آزمون مستقل است و بعد از تغییر runtime/artifact باطل می‌شود.

## ۶. معماری پیشنهادی بدون برنامه واسط
React/TypeScript UI، یک هسته محاسباتی مشترک، ModelManager، یک Worker برای inference، ذخیره محلی و یک backend کوچک برای بروکر. وزن‌ها روی دستگاه اجرا می‌شوند؛ backend محل اجرای مدل نیست. ساخت با AI Studio به معنی استفاده اجباری از Gemini API در محصول نیست.

| ماژول | مسئولیت و مرز |
| :--- | :--- |
| `apps/web` | UI، chart، RTL، PWA، Model Center و تأیید کاربر |
| `packages/core` | محاسبه deterministic؛ بدون واردکردن React/DOM/Node/AI/Broker |
| `packages/contracts` | schemaهای نسخه‌دار، reason codes و واحدها |
| `packages/application` | ترتیب دریافت، snapshot، inference، اعتبارسنجی و intent |
| `adapters/inference-webllm` | artifact سازگار، Worker و آزادکردن حافظه |
| `adapters/inference-litert-web` | آزمایش Gemma؛ lazy-loaded و اختیاری |
| `adapters/persistence-web` | IndexedDB تراکنشی برای journal و outbox محلی |
| `adapters/model-cache` | cache واقعی runtime و manifest سلامت فایل‌ها |
| `services/broker-gateway` | OAuth، اتصال cTrader، Demo guard، executor و outbox پایدار |
| `tests/evals` | سنجش فارسی، شواهد، خطاها و گزارش دستگاه |

### اصلاح ضروری مرز cTrader
پیشنهاد معماری وب: client secret، access/refresh token و application/account authentication بروکر همگی سمت server بمانند؛ مرورگر از session امن برنامه استفاده کند.

gateway درخواست دستگاه منتخب را اعتبارسنجی و به cTrader منتقل می‌کند. این سرور AI یا معامله‌گر خودکار نیست. هر دو مرورگر داده مجاز را می‌گیرند و محلی تحلیل می‌کنند.

«فقط دستگاه منتخب ارسال کند» در این معماری یعنی تنها درخواست تأییدشده همان session/epoch به بروکر پذیرفته شود؛ ارسال شبکه نهایی توسط gateway انجام می‌شود. این تفسیر و هزینه آن باید قبل از فعال‌سازی Demo به تأیید حامد برسد. طرح نباید همزمان ادعا کند secret هرگز به مرورگر نمی‌رسد ولی application authentication محتاج همان secret در مرورگر انجام می‌شود.

gateway برای هر account نوشتن را سریالی می‌کند، مالکیت را server-side می‌سنجد و state را در storage تراکنشی پایدار نگه می‌دارد. هزینه اتصال جلسه‌ای، timeout میزبان، reconnect و تعداد instanceها باید در W4 سنجیده شود؛ اگر در بودجه نمی‌گنجد Demo BLOCKED می‌شود، نه اینکه secret به client منتقل شود.

## ۷. قرارداد مدل و جدایی اختیار
ورودی مدل خلاصه عددی نسخه‌دار است، نه تمام tickها: snapshot ID، زمان، نماد، timeframe، ساختار محاسبه‌شده، candidate، evidence IDs، هزینه‌ها و داده‌های ناموجود.

ترتیب: core شواهد را محاسبه می‌کند؛ Analyst تحلیل کوتاه و uncertainty می‌دهد؛ Critic تناقض/کمبود شواهد را بررسی می‌کند؛ core خروجی را اعتبارسنجی می‌کند؛ کاربر intent را می‌بیند. Judge فقط در بررسی عمیق زمان‌دار و پس از سنجش لازم است؛ اختلاف حل‌نشده یعنی NO_TRADE، نه رأی‌گیری اجباری تا رسیدن به موافقت.

`AIReview` باید این‌ها را داشته باشد: `schema_version`، `role`، `status`، `snapshot_id`، `candidate_id`، `evidence_ids`، `invalidation_ids`، `concise_reason`، `uncertainties`، `expires_at`. وضعیت `status` از `APPROVE`، `REJECT`، `ABSTAIN` یا `ERROR` انتخاب می‌شود. APPROVE مجوز ارسال نیست.

حجم نهایی، risk cap، تشخیص Demo، authority، موجودی، price freshness و rounding، هیچ‌وقت اختیار مدل نیست. خروجی مدل در UI متن ساده و escaped باشد؛ JavaScript/HTML یا دستور ابزار اجرا نشود.

## ۸. دانلود، cache و آفلاین واقعی
manifest هر مدل شامل URLهای allowlisted، revision غیرشناور، نام و بایت فایل‌ها، hashهای تأییدشده، required_features، runtime version، model library WASM، tokenizer/config و وضعیت license review باشد.

برای WebLLM از cache backend پشتیبانی‌شده همان نسخه استفاده شود؛ مسیر پیش‌فرض فعلی Cache API است. Dedicated Worker وظیفه cache app shell/runtime را دارد؛ وظیفه service worker است. cache کردن API حساب، callback OAuth و token ممنوع. snapshot، prompt و گزارش خصوصی به analytics یا endpoint هوش مصنوعی ارسال نشوند. mode offline با قطع شبکه و کنترل درخواست‌ها آزموده شود؛ روی `navigator.onLine` تنها تکیه نشود.

## ۹. مدیریت توان و محدودیت‌های گوشی
در هر بار شروع، secure context، WebGPU adapter، shader-f16، buffer limits، فضای ذخیره و نتیجه load بررسی شود. RAM 16GB دستگاه به معنی 16GB قابل استفاده برای تب یا GPU نیست. اگر f16 موجود نبود، فقط artifact سازگار q4f32 آزموده شود.

context اولیه 2048، خروجی 256 تا 512 token و یک inference همزمان پیشنهاد می‌شود. Thinking در مسیر زمان‌حساس خاموش یا محدود با API مستند. کارکرد پس‌زمینه وعده داده نشود: وقتی صفحه hidden، session پایان‌یافته یا ارتباط کنترل قطع است، ورود جدید ممنوع؛ Worker در صورت امکان لغو و نتیجه دیررس در هر حال discard شود.

## ۱۰. آزمون مقایسه‌ای مدل‌ها
یک corpus ثابت پیشنهادی ۱۲۰ مورد: ۲۰ فهم فارسی، ۲۵ grounding روی snapshot، ۲۰ تناقض/داده ناقص، ۲۰ خروجی schema/evidence، ۱۵ prompt injection و ۲۰ شرایط انقضا/رد/ابهام.

Gate پیشنهادی: تمام خروجی‌های خراب در validator رد شوند؛ صفر پذیرش evidence جعلی در تست‌های adversarial؛ حداقل ۹۵٪ schema معتبر و grounding درست در corpus؛ تحلیل Intraday در p95 حداکثر ۳۰ ثانیه؛ بدون crash در ۳۰ دقیقه.

## ۱۱. بازار، تحلیل و استراتژی آزمایشی
نسخه اول cTrader Forex/Gold با XAUUSD و EURUSD پس از تطبیق شناسه بروکر.
قواعد baseline پیشنهادی S0:
* کندل بسته، UTC و بازه نیمه‌باز؛ Wilder ATR(14) با warmup معتبر.
* swing با دو کندل چپ و راست؛ tie بدون pivot؛ زمان شناخت پس از بسته‌شدن دو کندل راست.
* context یک‌ساعته: HL+HH صعودی، LL+LH نزولی، بقیه neutral؛ تعارض H4 مانع ورود.
* sweep: عبور حداقل یک tick از swing تأییدشده و بسته‌شدن داخل سطح.
* BOS: close بیرون swing حداقل 0.1 ATR همان TF.
* displacement: بدنه حداقل 0.8 ATR و نسبت بدنه به range حداقل 0.6؛ range صفر رد.
* FVG سه کندل بسته: فاصله low سوم و high اول برای bullish؛ معکوس برای bearish؛ حداقل 0.05 ATR.
* setup حداکثر شش کندل M15 پس از sweep؛ entry بررسی retest در M5؛ midpoint فقط فرض limit است، نه fill تضمین‌شده.
* SL بیرون sweep extreme با buffer برابر max یک tick و 0.1 ATR(M5).
* TP اولین swing مخالف معتبر با RR خالص کافی؛ نبود هدف = رد.

## ۱۲. ریسک، خبر و مدیریت سفارش
پیشنهاد Demo: ریسک ثابت هر معامله ۰.۲۵٪، ریسک باز همراه reservation سفارش‌های pending حداکثر ۱٪، سه position منطقی، RR حداقل ۱.۵ پس از هزینه. سقف روزانه ۱.۵٪ و ۳٪ drawdown.

چرخه intent:
`DRAFT -> VALIDATED -> AWAITING_CONFIRMATION -> SUBMITTING -> ACKNOWLEDGED -> PARTIALLY_FILLED -> FILLED -> CANCEL_PENDING -> CANCELLED -> REJECTED -> EXPIRED -> UNKNOWN_RECONCILE_REQUIRED`

وضعیت محافظ و position جدا باشد. outbox محلی برای draft است؛ gateway outbox پایدار و unique intent key برای write دارد. timeout یا قطع ack >= توقف و reconciliation، هرگز resend کور.

## ۱۳. دو دستگاه و استقلال واقعی
دو دستگاه، دو cache مدل و دو worker مستقل. gateway یک executor grant شامل session ID، device label، epoch، expiry و وضعیت handoff دارد. تمام writeها باید از همان gateway عبور کنند؛ هیچ credential مجاز به write در مرورگر باقی نماند.

## ۱۴. ذخیره، امنیت و بودجه
* **محلی:** تنظیمات، replay، AIReview، evidence، snapshot، journal و metadata مدل در IndexedDB؛ فایل مدل در cache اختصاصی.
* **سرور:** tokenها رمزگذاری‌شده و با حداقل دسترسی، session امن، executor و outbox و audit log.
* **بودجه:** سقف ۲۰ دلار استرالیا (AUD 20) در ماه برای کل سرویس‌های جاری.
* **هوش مصنوعی:** cloud AI پیش‌فرض خاموش؛ fallback مخفی Groq/Gemini ممنوع.
