# کتابچه راهنمای عملیاتی و استقرار: Hamed Trading Lab (نسخه ۳.۴ کاندیدای انتشار)

این سند راهنمای جامع عملیاتی برای حامد جهت استقرار، راه‌اندازی، پایش، رفع اشکال و مدیریت بحران (Disaster Recovery) پلتفرم معاملاتی آزمایشگاهی است.

---

## ۱. اصول اساسی و محدودیت‌های عملیاتی
- **محیط اجرایی:** نسخه فعلی به عنوان یک **Web App / PWA** تمام‌پشته (React 19 + Next.js App Router + TypeScript) طراحی شده و در مرورگرهای Windows و Android (از جمله دستگاه‌های با پردازنده ARM و نمایشگرهای تاشو مانند Pixel 9 Pro Fold) اجرا می‌شود.
- **محیط معاملاتی مجاز:** **فقط و فقط cTrader Demo**. هرگونه تلاش برای اتصال یا ارسال سفارش به حساب‌های Real یا Live به‌طور سخت‌گیرانه توسط سرور مسدود می‌شود (Fail-Closed).
- **قانون تعلیق پس‌زمینه وب:** در محیط مرورگر وب، پس از بسته‌شدن تب یا تعلیق پس‌زمینه توسط سیستم‌عامل اندروید، هیچ سفارشی پردازش نمی‌شود و وضعیت به حالت ایمن مسدود می‌گردد.
- **سقف بودجه عملیاتی:** حداکثر ۲۰ دلار استرالیا (AUD 20) در ماه. کلیه محاسبات، ریت‌لیمیتر، و گاوصندوق توکن‌ها به‌صورت سروری محلی (In-Memory / Crypto) و بدون وابستگی به پایگاه‌داده‌های ابری گران‌قیمت طراحی شده‌اند.

---

## ۲. متغیرهای محیطی و کلیدهای محرمانه
تمام متغیرهای زیر باید **صرفاً در سمت سرور** (تنظیمات محیطی کانتینر Cloud Run یا فایل `.env.local`) تعریف شوند:

| نام متغیر | الزامی؟ | توضیحات |
| :--- | :--- | :--- |
| `APP_URL` | بله | آدرس پایه اپلیکیشن (مثلاً `http://localhost:3000` یا URL اختصاصی کلودران) |
| `GEMINI_API_KEY` | اختیاری | کلید رسمی Google AI Studio برای خط لوله تحلیل‌گر و منتقد هوش مصنوعی |
| `CTRADER_CLIENT_ID` | اختیاری (دمو) | شناسه برنامه در پورتال cTrader Open API |
| `CTRADER_CLIENT_SECRET` | اختیاری (دمو) | سکرت برنامه در cTrader Open API (فقط سرور) |
| `CTRADER_REDIRECT_URI` | اختیاری (دمو) | آدرس بازگشت OAuth (مثلاً `https://your-domain/api/auth/ctrader/callback`) |
| `CTRADER_ENVIRONMENT` | پیش‌فرض `demo` | مقدار باید حتماً `demo` باشد؛ هر مقدار دیگر رد می‌شود. |
| `CTRADER_TOKEN_ENCRYPTION_KEY` | اختیاری | کلید یا عبارت اولیه جهت تولید کلید ۲۵۶ بیتی گاوصندوق AES-256-GCM |

> ⚠️ **هشدار امنیتی:** هیچ‌یک از متغیرهای فوق نباید با پیشوند `NEXT_PUBLIC_` تعریف شوند.

## ۳. مراحل راه‌اندازی و بیلد محلی
```bash
# ۱. نصب وابستگی‌های پروژه
npm install

# ۲. کپی متغیرهای نمونه
cp .env.example .env.local

# ۳. اجرای تست‌های لینتینگ و بررسی استاتیک
npm run lint

# ۴. کامپایل بیلد تولیدی (Production Build)
npm run build

# ۵. راه‌اندازی سرور پروداکشن
npm run start
```

## ۴. چک‌لیست بررسی سلامت و آزمون‌های خودکار (Smoke Verification)
پیش از استفاده، حامد می‌تواند با مراجعه به اندپوینت‌های زیر از سلامت ۱۰۰٪ سیستم اطمینان حاصل کند:

1. **بررسی زنده سلامت سیستم:**
   ```bash
   curl -s http://localhost:3000/api/health
   ```
   - خروجی باید شامل `"status": "HEALTHY"`، نسخه `3.4.0-RC` و وضعیت فعال گاوصندوق باشد.

2. **اجرای آزمون‌های راستی‌آزمایی ۳۲‌گانه:**
   ```bash
   curl -s http://localhost:3000/api/verify-tests
   ```
   - تمام ۳۲ آزمون واحدهای ۱ تا ۹ باید با `"status": "SUCCESS"` و نرخ ۱۰۰٪ پاس شوند.

3. **دریافت وضعیت امنیتی و اسنپ‌شات:**
   ```bash
   curl -s http://localhost:3000/api/recovery
   ```

## ۵. دستورالعمل مدیریت بحران (Disaster Recovery Runbook)
در صورت بروز رخدادهایی نظیر قطع ناگهانی برق، راه‌اندازی مجدد سرور، قطعی شبکه یا بروز خطای ۴۲۹:

1. **انتقال خودکار به وضعیت ایمن (Cold Crash Recovery):**
   - به محض راه‌اندازی مجدد سرور، تمام سفارشاتی که در لحظه کرش در وضعیت معلق `SUBMITTING` بودند، به وضعیت `UNKNOWN_RECONCILE_REQUIRED` منتقل می‌شوند.
   - تا زمان تعیین تکلیف قطعی سفارش از سمت بروکر cTrader، ثبت هرگونه سفارش جدید به‌صورت خودکار مسدود می‌شود.

2. **بازتطبیق سفارش (Reconciliation):**
   - حامد می‌تواند در کارت صندوق تراکنشی (Transactional Outbox) روی دکمه **«تطبیق اجباری با cTrader»** کلیک کند تا وضعیت نهایی استعلام و صف آزاد گردد.

3. **پشتیبان‌گیری اضطراری:**
   - در پنل امنیت، دکمه **«دانلود اسنپ‌شات با امضای SHA-256»** را بفشارید تا نسخه پشتیبان رمزنگاری‌شده ذخیره گردد.

## ۶. گردش‌کار معامله دمو (Step-by-Step Demo Flow)
1. انتخاب دستگاه مجری (Designated Device) و ارسال ضربان قلب (Heartbeat).
2. بررسی کاندیدای معامله استراتژی S0 در نماد XAUUSD یا EURUSD.
3. مشاهده پیش‌نمایش کنترل ریسک (سقف ۰٫۲۵٪ و کسر کارمزد بروکر).
4. تایید دستی و صریح سفارش توسط کاربر در پنجره مودال فارسی.
5. ارسال به صندوق خروجی با شناسه یکتای تسریعی (Idempotency Key) جهت جلوگیری از ثبت تکراری.
6. دریافت شماره سفارش بروکر و ثبت خودکار در ژورنال معاملات.
